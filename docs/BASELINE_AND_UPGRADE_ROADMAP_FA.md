## نکات فنی مشاهده‌شده در نسخه اولیه
- score-manager.js مستقیماً از REST API پایگاه داده Firebase Realtime Database استفاده می‌کند.
- شناسه کاربر در مرورگر از initDataUnsafe تلگرام خوانده می‌شود؛ این داده به‌تنهایی اعتبارسنجی سمت سرور محسوب نمی‌شود.
- امتیازها و پاداش دعوت/اسپانسر از سمت کلاینت به Firebase نوشته می‌شوند.
- تشخیص تکراری بودن بعضی رویدادها در localStorage مرورگر انجام می‌شود و قابل اتکا به‌عنوان کنترل ضدتقلب سمت سرور نیست.
- دو بازی giraffe.html و math-sting.html در نسخه بررسی‌شده، اتصال آشکاری به ChalbaziScore نداشتند؛ پیش از یکپارچه‌سازی باید نحوه امتیازدهی هر بازی جداگانه بررسی شود.

## نقشه ارتقا (به ترتیب وابستگی)
1. ایمن‌سازی Firebase و انتقال نوشتن امتیاز/پاداش به سرویس سمت سرور؛ بدون این مرحله، افزودن اقتصاد امتیازی یا رقابت جایزه‌دار ریسک تقلب دارد.
2. یکپارچه‌سازی ثبت امتیاز همه بازی‌ها با رویدادهای معتبر و یکتا.
3. پروفایل بازیکن، سطح و نشان‌ها بر پایه آمار قابل اعتماد.
4. چالش دوستان و اشتراک نتیجه با لینک/پارامتر دعوت معتبر.
5. چالش روزانه با شرایط یکسان و رتبه‌بندی مستقل.
6. بازطراحی صفحه خانه به گیم‌هاب با دسته‌بندی، بازی ویژه و ادامه بازی.
7. توسعه لیگ‌ها، مسابقات گروهی و پنل مدیریت.

## هشدار امنیتی مهم
در تاریخ 2026-11-28 تصویری از ایمیل Firebase دریافت شد که هشدار می‌دهد قوانین پایگاه داده chalbazi-word-default-rtdb اجازه خواندن و نوشتن عمومی روی کل پایگاه داده را می‌دهد. این وضعیت باید پیش از انتشار ارتقا رفع شود. بستن فوری همه دسترسی‌ها ممکن است قابلیت‌های فعلی متکی به REST API را از کار بیندازد؛ بنابراین ابتدا از داده‌ها نسخه پشتیبان تهیه و سپس احراز هویت/قواعد مسیرمحور و سرویس سمت سرور پیاده‌سازی شود.
